# RFC: DomainPack 契约与 NetworkOps 提取（v0.16.0）

- **状态**：评审通过（对照章程铁律逐条自评，见 §8），待实现
- **证明命题**：平台非为单一领域定制
- **前置事实**：v0.15.0 已发布（后端 446 / Console 17 全绿）；v0.15 收口清单 ②③ 已完成，① 并入本 RFC §5.1

---

## 1. 目标

1. 定义 `DomainPackSpec` 契约（Pydantic 模型）：领域资产（能力/Agent/工作流/权限/角色/知识库/评测集/API/UI）以声明式清单注册进平台；
2. 注册器 `PackRegistry`：register → schema 校验 → 治理一致性校验（fail-fast）→ 冲突校验 → 全量注册 → enable；
3. **两个** pack 落地：`networkops`（存量网络域提取）与 `embeddedops`（v0.15 资产迁入）——只有单一 pack 无法证明"非为单一领域定制"，且 core 零领域代码的验收必然要求两域都迁出；
4. core（平台运行时）零领域代码，以可测断言固守。

## 2. 非目标（显式不做）

| 项 | 表态 | 理由与触发条件 |
| --- | --- | --- |
| Pack Installer（本地安装/卸载/依赖解析） | 不做 | v0.20 证明命题；v0.16 只做进程内注册 |
| Domain lifecycle 完整状态机（disable 排空/upgrade/rollback） | 最小版 | 契约留 `lifecycle.status` 占位字段（enabled/disabled），语义 v0.20 实现 |
| ui_extensions 动态注入 Console | 最小版 | 契约字段接受注册并校验 schema，Console 仍静态内置页面；动态导航 v0.20 评估 |
| Python 包整体更名（`network_agent_rag` → `agentos.*`） | 不做 | 铁律 17：对外命名未查重定稿前更名是双重迁移浪费；触发条件：命名查重定稿后单独立项。`packs/` 目录结构先落 |
| pack 间依赖拓扑安装 | 不做 | 仅做依赖存在性声明校验；安装是 v0.20 Installer 职责 |
| 动态权限字符串（脱离 enum 的完全开放权限） | 不做 | v0.16 权限目录 = 注册表视图（见 §4.3），枚举语义保持；完全动态化待 v0.20 |

## 3. 契约（代码草案）

```python
# src/network_agent_rag/packs/models.py

class RouterSpec(PolicyModel):
    prefix: str                      # e.g. "/embedded"
    factory: str                     # import path: "network_agent_rag.api.embedded:create_embedded_router"

class UiExtensionSpec(PolicyModel):
    view_id: str; label: str; glyph: str   # v0.16 仅注册校验，Console 静态

class PermissionSpec(PolicyModel):
    name: str                        # 必须命中平台权限目录（§4.3）
    description: str

class RoleSpec(PolicyModel):
    name: str
    permissions: tuple[str, ...]     # 必须是本 pack 或平台权限
    description: str

class KnowledgeCollectionSpec(PolicyModel):
    name: str                        # = Chroma collection 名
    directory: str                   # 语料目录（相对仓库根）

class DomainPackSpec(PolicyModel):
    name: str                        # ^[a-z][a-z0-9_]*$，如 "networkops" / "embeddedops"
    version: str                     # 语义化版本
    description: str
    lifecycle: LifecycleSpec = LifecycleSpec()          # 占位：status: enabled|disabled
    capabilities: tuple[Capability, ...] = ()           # 复用现有模型（含 metadata/backend）
    agent_factories: tuple[str, ...] = ()               # import path，惰性导入校验
    workflow_factories: tuple[str, ...] = ()
    permissions: tuple[PermissionSpec, ...]             # 治理资产，必须非空
    roles: tuple[RoleSpec, ...]                         # 治理资产，必须非空
    knowledge_collections: tuple[KnowledgeCollectionSpec, ...] = ()
    evaluation_cases: tuple[str, ...] = ()              # 目录（随 pack 走，铁律 10）
    api_routers: tuple[RouterSpec, ...] = ()
    ui_extensions: tuple[UiExtensionSpec, ...] = ()
    depends_on: tuple[str, ...] = ()                    # pack 名，仅存在性校验
```

**注册流程（fail-fast 顺序即校验顺序）**：

```
register(spec)
  1. schema 校验（Pydantic，含 name/version 格式）
  2. (name, version) 冲突：同 name 同 version 拒绝；同 name 新 version 允许（升级是 v0.20 语义，v0.16 拒绝同 name 多 version 注册以防误用）
  3. depends_on 存在性
  4. 治理一致性：
     a. PermissionSpec.name ∈ 平台权限目录
     b. RoleSpec.permissions ⊆ 本 pack 权限 ∪ 平台权限
     c. capability.permission ∈ 本 pack 声明的权限 ∪ 平台权限
     d. capability.permission 与 PolicyEngine 操作白名单对齐（铁律 6 —— v0.15 收口项①的正式形态）
  5. import path 解析校验（agent/workflow/router factory 可导入且签名匹配）
  6. 全量注册：capabilities 入 CapabilityRegistry、权限/角色入目录、评测集路径登记
  7. enable：lifecycle.status = enabled（API 装配只挂载 enabled pack 的 router）
```

## 4. 关键设计裁决

### 4.1 目录结构（不更名 Python 包）

```
packs/
  networkops/
    manifest.py          # DomainPackSpec 实例（唯一事实源）
    permissions.py       # 权限/角色声明（迁移自 auth/models.py 网络域部分）
    agents/...           # 自 src/network_agent_rag/agents/{multi_agent,enterprise,workflow...} 迁移
    domain/topology.py   # 自 src/network_agent_rag/domain/topology.py 迁移
    knowledge/diagnosis/ # 自 knowledge/diagnosis 迁移（collection: network_knowledge）
    evaluation/network_*.jsonl
  embeddedops/
    manifest.py
    ...                  # v0.15 全部 embedded 资产迁入
src/network_agent_rag/
  packs/                 # 契约 + PackRegistry（平台运行时）
  capability/ policy/ auth/ audit/ observability/ storage/ rag/ artifact/
  api/（core 装配：main.py 按 enabled packs 挂载 router）
```

迁移原则：**文件移动 + import 更新 + 测试路径更新**，不改行为；446 存量断言不改语义（importlib/路径断言除外，随迁移同步更新）。`domain/task/`（统一 Task 模型）为平台资产留在 core。

### 4.2 权限目录（Permission Catalog）

`auth/models.py` 中 `Permission`/`Role` 枚举现状：网络域与嵌入式域权限混在一个 enum，属领域泄漏。v0.16 裁决：

- 新增 `PermissionCatalog`（注册表）：pack 注册时写入其权限/角色；
- `auth.models.Permission/Role` 保持 StrEnum 不变（存量 RBAC/JWT/Policy 序列化依赖枚举值字符串），但**枚举成员从"领域所有权"降级为"平台预检清单"**：pack 注册校验 4a 改为"目录中存在或与预检清单命中"；
- 枚举成员断言测试（`test_rbac_models` 等）迁移至对应 pack 测试并按 pack 重写；
- 完全动态权限（无 enum）推迟至 v0.20（Installer 引入外部 pack 时必须），届时以破坏性 RFC 处理序列化兼容。

### 4.3 core 零领域代码的可测断言

新增架构测试（import-linter 式，自研约 40 行，不引依赖）：

### 4.4 评测集随 pack 走（铁律 10）

`evaluation/embedded_cases/` → `packs/embeddedops/evaluation/cases/`；`benchmarks/network_*.jsonl` → `packs/networkops/evaluation/`。`load_embedded_cases` 默认目录参数同步迁移；中央 `evaluation/`（runner/聚合）保留在 core。

## 5. 实施顺序（拆提交，利于 bisect）

1. **packs 契约 + PackRegistry + 全部校验**（含 v0.15 收口项①：capability.permission ↔ Policy 一致性测试在此落地）；新增测试：注册/校验 fail-fast 全路径
   > 风险敞口备注：v0.15.0 发布时一致性校验尚未存在，capability 与 policy 配置在此窗口内可能漂移；本提交落地即敞口关闭，注册器 docstring 同步注明。
2. **embeddedops pack 迁移**（最新最小，先走通契约）；`tests/test_embedded_*` 路径更新，语义断言不变
3. **networkops pack 迁移**（网络域 agents/权限/collection/workflow/API/console 数据源全量走 pack 接口）；存量测试迁移
4. **main.py 装配改为 pack 驱动** + 架构测试（§4.3）落地
5. **README Roadmap 更新 + 命名查重记录 + 版本 0.16.0 + tag**（查重结论无论结果如何写入 RFC 附录，作为铁律 17 的执行证据）

每步门禁：全量测试绿才进下一步。

## 6. 验收清单（定稿：用户 10 项为基座 + RFC diff 补充 a–e，合并后共 15 项）

1. 后端全量测试零回归（基线 446 + 新增），Console 17 项全绿
2. networkops 与 embeddedops 两 pack 全量资产走注册：agents、capabilities、workflows、permissions、roles、knowledge collections、api_routers
3. core 零领域代码由 import 扫描测试强制：core 模块 import packs/ 即测试失败（无检验机制的验收项不算数）
4. Registry↔PolicyEngine 一致性校验：pack 注册时 permission 不匹配 → fail-fast（v0.15 收口项①在此兑现，§5 步骤 1 已注明风险敞口）
5. 未知权限注册 → fail-fast（权限目录边界，动态化推迟 v0.20 的显式记录）
6. (name, version) 冲突注册 → fail-fast；多版本共存与 resolve 选版行为保持
7. lifecycle / ui_extensions 占位字段：schema 校验接受、运行时显式忽略——两者都有测试
8. 评测集随 pack 迁移：embedded_cases 挪入 embedded pack，`make embedded-demo` 端到端不回归
9. 知识 collection 所有权随 pack：注册时初始化 embedded_knowledge / network_knowledge，RAG 跨库检索行为不变
10. 证明命题表述为"契约可容纳两个既有领域"（证伪性检验）；通用性证明留给 v0.18，不自我拔高
- a.（RFC 补充）agent/workflow/router factory import path 不可导入或签名不符 → fail-fast 测试
- b.（RFC 补充）角色越权引用（RoleSpec.permissions 超出本 pack ∪ 平台权限）→ fail-fast 测试
- c.（RFC 补充）双 pack 同时 enabled 下 `/api/v1/console/*` 与 `/api/v1/embedded/*` 共存可达（API 测试）
- d.（RFC 补充）存量语义断言零修改约束：迁移仅允许更新路径/importlib 断言，作为门禁条款而非单测
- e.（RFC 补充）命名查重结论写入 RFC 附录（与铁律 17 挂账清偿合并，§9 附录）

前端范围锁定（ui_extensions 仅登记 schema、Console 代码不动）作为约束条款，不占验收位。

## 7. 风险与回滚

- 最大风险：networkops 迁移动面大（agents/enterprise 等约 20+ 文件）。缓解：纯移动 + 机械 import 更新 + 分步提交；每步全量门禁即为回滚锚点。
- checkpoint 兼容：不改任何 LangGraph 图结构（铁律 3），存量 checkpoint 不受影响。
- Console：静态页面不动，仅数据源 URL 不变；无前端行为风险。

## 9. 附录：命名查重结论（铁律 17 挂账清偿，2026-08-23）

**结论：裸名 "AgentOS" 不可用于对外发布。**

活跃同名/强关联项目：

| 项目 | 形态 | 冲突强度 |
| --- | --- | --- |
| Agno `agno-agi/agno` 的 **AgentOS runtime + UI** | 大型开源 Agent 平台运行时 | 高（同名词 + 同品类） |
| FramersLab `framerslab/agentos`（npm `@framers/agentos`） | 生产级 TS Agent 框架 | 高（npm 包名已被占） |
| AG2（原 AutoGen）`ag2ai/ag2` | 自称 "Open-Source AgentOS" | 中（营销用语占用） |
| iii-experimental `agentos` | 自进化 Agent OS | 中 |
| agentops.ai | 不同名（AgentOps），铁律 17 已记录 | 低 |

裁决：
1. **"AgentOS" 保留为内部代号**（章程、RFC、代码注释继续使用，零成本）；
2. **对外发布（PyPI/GitHub 公开更名/Docker Hub）必须使用差异化名称**，候选（领域词 + OS 语义）：定名前再出一轮候选清单评审；
3. 本仓库 Python 包更名（RFC §2 已裁决"不做"）不受影响——更名本来就在查重定稿之后。

参考：[agno-agi/agno](https://github.com/agno-agi/agno)、[framerslab/agentos](https://github.com/framerslab/agentos)、[ag2ai/ag2](https://github.com/ag2ai/ag2)、[iii-experimental/agentos](https://github.com/iii-experimental/agentos)

## 10. Phase 0 结论：checkpoint 兼容性调查（步骤 2 阻塞项，已完成）

**机制**（证据：`.venv/.../langgraph/checkpoint/serde/`）：

1. 序列化器为 `JsonPlusSerializer`（ormsgpack），`pickle_fallback` 默认 **False**——未知类型写入时抛 `MsgpackEncodeError`，不落 pickle；
2. 类引用路径存在：自定义对象编码为 `module + qualname` 构造器 ext code（EXT_PYDANTIC_V2 等）；
3. 本仓库默认 `LANGGRAPH_STRICT_MSGPACK=true`（Settings → enterprise API 入口 setdefault），反序列化 allowlist 仅含 stdlib/langchain-core/langgraph 类型——域类引用在**读取时**响亮失败；
4. 关键不对称（评审必增项指出）：**fail-loud 只发生在读，不发生在写**。若 v0.15 有任何未 dump 对象进入 state，写入成功、只有新布局下加载才会炸；"新代码自建 checkpoint 再读回"是循环论证。

**裁决：非破坏性迁移，不需要 re-export shim。**

**可执行证据（golden checkpoint fixtures，替代审计结论）**：

- `tests/fixtures/v015_embedded_approval.sqlite3`——v0.15 布局下推进到审批挂起 interrupt 的完整 checkpoint（最硬场景：state + interrupt payload 双重解码）；固定时钟 2026-08-23T12:00:00Z（防审批 TTL 随墙钟腐化）；
- `tests/fixtures/v015_embedded_midflight.sqlite3`——HardwareAgent 完成后即停的 mid-flight checkpoint；
- 生成脚本 `scripts/generate_v015_checkpoint_fixture.py`（仅可在 v0.15 布局运行，fixture 是记录性产物）；
- 迁移提交附带 `tests/test_v015_checkpoint_recovery.py`：**新布局**加载 fixture → 断言 state 与 approval payload 完整恢复 → resume 审批至 PASSED；mid-flight fixture 续跑到同一终点。此测试是"旧格式恢复"这一事实的存证，非新代码自证。
- fixture 自测已在生成时完成（当前布局恢复 + resume PASSED），后续失败可归因于布局变更而非坏 fixture。
