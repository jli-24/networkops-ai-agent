# SPI / I2C 通信故障案例库

## 案例 1：SPI 读取传感器全 0xFF

现象：ESP32 通过 SPI 读取温湿度传感器 SHT3x，返回值恒为 0xFF。

排查过程：

1. 检查 CS 片选脚：CS 未在每次传输前拉低、传输后拉高。
2. 检查时钟模式（CPOL/CPHA）：传感器要求 Mode 0，驱动配置成 Mode 3 导致移位错位。
3. 检查 MISO/MOSI 是否接反。

根因：SPI 时钟极性与相位配置错误（CPOL/CPHA 不匹配）。

解决方案：将 SPI 初始化为 Mode 0（CPOL=0, CPHA=0）；用逻辑分析仪确认时钟空闲电平为低、第一个边沿采样。

## 案例 2：SPI 时钟过快导致数据错乱

现象：STM32F103 与 W25Q64 Flash 通信，时钟设为 18MHz 时偶发读出错误数据。

根因：超过器件最大时钟频率（W25Q64 在 3.3V 下最高约 33MHz，但走线过长引入信号完整性问题）。

解决方案：时钟降至 9MHz；缩短走线或增加串联电阻改善信号质量；关键数据使用 CRC 校验。

## 案例 3：I2C 设备地址冲突

现象：总线上挂载两个器件后，两个地址都读不到数据。

根因：两个器件默认地址相同（0x23），产生地址冲突。

解决方案：通过 ADDR 引脚改变其中一个器件的地址（0x23/0x5C），或在架构上使用 I2C 多路复用器 TCA9548A。

## 案例 4：I2C 总线死锁

现象：某传感器在复位时将 SDA 拉低，总线死锁，后续所有传输失败（START 后无 ACK）。

根因：从机在主机传输中途复位，时钟拉伸未释放 SDA。

解决方案：总线恢复序列——发送 9 个 SCL 时钟脉冲 + STOP 条件；在驱动初始化时实现 `i2c_bus_recover()`。

## 案例 5：ESP32 Wi-Fi 与 SPI 共存干扰

现象：ESP32 开启 Wi-Fi 后，SPI 采集偶发超时。

根因：Wi-Fi 射频占用造成任务抢占，SPI 传输被打断且未加互斥锁。

解决方案：SPI 传输临界区加互斥锁；将采集任务绑定到指定核心（ESP32 双核）；提高采集任务优先级。
